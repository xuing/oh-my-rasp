# Development reference

This directory contains the two durable technical ledgers that must be kept in
sync with the Java agent source code.

## algorithm-coverage.md

The detector ledger. It records every hook point and detection algorithm
implemented in `DetectorEngine`, organised by runtime era (Java 25 primary,
Java 8/11/17 backports) and attack family. When you add, remove, or rename a
detector or change an acceptance key, update this file in the same commit.

The Vulhub progress cross-reference at the top of the file points to
`vulhub-coverage.md` for per-CVE replay status.

## vulhub-coverage.md

The Vulhub replay checklist. Each entry records the Vulhub component, CVE or
path, the expected baseline proof of exploitation, the matching Java LTS agent,
and the protected-side block condition. A checked item means the repository has
a behavior rule or sink hook and passing playground/acceptance coverage.

`java-agent/scripts/check-vulhub-java-coverage.py` cross-references this
checklist against the acceptance scripts in `java-agent/scripts/`. CI fails if a
checked entry has no corresponding acceptance script, or if an acceptance script
covers a target not listed in this file. Update this file in the same patch as
any new Vulhub target, moving candidates to the covered section only after both
baseline exploitation and protected-side block are confirmed.

## Auto-generated agent docs

Two files in `java-agent/docs/` are generated by scripts and must not be edited
by hand:

| File | Generator |
|---|---|
| `java-agent/docs/DETECTION-COVERAGE.md` | `java-agent/scripts/gen-detection-coverage.py` |
| `java-agent/docs/FALSE-POSITIVE-REPORT.md` | `java-agent/scripts/run-fp-report.sh` |

CI checks that these files are up to date with the source. If you change a
detector, regenerate both files and include them in the same pull request:

```bash
python java-agent/scripts/gen-detection-coverage.py
bash java-agent/scripts/run-fp-report.sh
```

The CI job fails on any stale diff in either file.
